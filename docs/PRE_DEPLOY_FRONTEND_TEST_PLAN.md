## Result states
PASS = verified locally/simulator. PASS-WITH-LIMITATION = code/simulator verified but true browser/device/network runtime requires Gate 4. FAIL = defect found. BLOCKED = cannot be tested locally without deployment/device/account context.

## Reporting
Each test is reported back with its ID, result, evidence, defect/fix if any, and remaining limitation. The checklist is updated as testing proceeds. No deployment occurs until the pre-deploy checklist is complete and release decision is explicit.

- RES-002: reconnect conflict protection PASS-WITH-LIMITATION. Offline queue entries retain the match revision from the moment the result was captured. Manual Retry Sync sends that exact `expectedRevision`; it does not fetch a newer revision and silently retry. `saveClubChallengeScore` compares the supplied revision to the authoritative match revision before any update and returns HTTP 409 with both current server state and the attempted score when stale. The client retains conflicted entries in the pending queue, reports that nothing was overwritten, and logs the conflict for manual review. Matching revisions can save and advance normally. Reconnect itself only announces that pending results are ready; it never auto-submits them. 16 static/simulation assertions, Gate 3 final rehearsal, ESLint and production build PASS; real two-device/network reconnect remains Gate 4.
- RES-004: timer sleep/reopen resynchronisation PASS-WITH-FIX/LIMITATION. The authoritative timer remains server-persisted through `timer_state_json` with `started_at`, `remaining_seconds` and `timer_revision`; internal and public displays recalculate remaining time from that persisted timestamp, so a normal reopen reconstructs the timer rather than restarting a local countdown. The test found that foregrounding a sleeping/backgrounded tab relied only on the existing 1s local tick and 5s state polling. Added `visibilitychange` and window-focus handlers to immediately refresh the local clock and authoritative event/match state internally, and immediately reload the public Hall Display. 15 static assertions, Gate 3 final rehearsal, ESLint and production build PASS. Device clock skew is still a known limitation because the rendered countdown compares the server-written timestamp with local `Date.now()`; real phone/tablet sleep, background throttling and clock-skew behaviour remain Gate 4.
