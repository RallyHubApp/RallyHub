## Result states
PASS = verified locally/simulator. PASS-WITH-LIMITATION = code/simulator verified but true browser/device/network runtime requires Gate 4. FAIL = defect found. BLOCKED = cannot be tested locally without deployment/device/account context.

## Reporting
Each test is reported back with its ID, result, evidence, defect/fix if any, and remaining limitation. The checklist is updated as testing proceeds. No deployment occurs until the pre-deploy checklist is complete and release decision is explicit.

- CCUI-008: court/time disruption workflow PASS-WITH-FIX. Gate 3 final rehearsal, ESLint and production build PASS. Live backend invocation remains a Gate 4/runtime check.
- CCUI-009: offline scoring retention/retry contract PASS-WITH-LIMITATION. ScoreCard checks offline state before invoking the backend and labels the result UNSYNCHRONISED; connection-loss failures queue the same payload locally. Pending results are persisted per tournament in localStorage and restored after reopening, with one pending item per match. Reconnect surfaces the unsynchronised count and Retry Sync action. Retry reuses the original `expectedRevision`; only successful saves are removed, while stale conflicts and transient failures remain queued and are reported for manual review with an explicit `nothing was overwritten` warning. Mixed success/conflict/failure simulation and the full Gate 3 rehearsal PASS, as do ESLint and production build. Gate 3 final rehearsal, ESLint and production build PASS. New backend Showcase invocation remains a Gate 4 live-runtime check.
- CCUI-012: Player of Tournament lifecycle PASS-WITH-FIX/LIMITATION.
